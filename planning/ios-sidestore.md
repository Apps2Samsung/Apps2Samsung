# Apps2Samsung on iPhone through SideStore

Proposed path, 17 October 2026. A plan, not an implemented or tested iOS release. Companion to
[#753](https://github.com/Apps2Samsung/Apps2Samsung/issues/753) (the iOS head) and
[#755](https://github.com/Apps2Samsung/Apps2Samsung/issues/755) (v3 and the stores).

## Goal

Let users run Apps2Samsung on their iPhone **without an Apple Developer Program subscription**.
SideStore installs and signs the app on the phone with the user's own free Apple ID; Apps2Samsung
itself talks to the Samsung TV exactly as the Android app does. For iOS this is the equivalent of the
Android F-Droid/Obtainium channel: the free route next to the store route that v3 adds.

## Where we already are

- **The native port exists.** `Apps2Samsung.Mobile` builds for `net10.0-ios` since v2.8.3 (#754):
  same pages, services and in-process SDB engine as Android, with `Platforms/iOS` for the Samsung
  sign-in WebView, the file picker and the Info.plist entries. It is compile-checked on every PR by
  the `Mobile (iOS)` job (GitHub's `xcode-27` runner, simulator target, unsigned).
- **Nothing has run on a device yet.** The on-device checklist is #753 step 5. SideStore is also the
  cheapest way to get there: an unsigned IPA from CI plus a free Apple ID puts the app on a real
  iPhone, so the device probe does not wait for a Mac or a paid account.

## Build and release

1. **Device IPA from CI, unsigned.** A release-workflow job on `xcode-27` runs
   `dotnet publish Apps2Samsung.Mobile/Apps2Samsung.Mobile.csproj -c Release -f net10.0-ios -r ios-arm64 -p:EnableCodeSigning=false -p:BuildIpa=true`
   and uploads `Apps2Samsung-vX.Y.Z-ios-unsigned.ipa` next to the APK. Unsigned on purpose: SideStore
   re-signs each install with that user's Apple ID, and no shared personal account or signing
   material ever belongs in the repo or in CI secrets. This publish is also the first time the iOS
   ahead-of-time compiler and trimmer see BouncyCastle and `System.Security.Cryptography.Xml`, so
   expect a round of trimmer roots or `TrimMode` adjustments here.
2. **Start on the beta channel.** Add the job to `beta-prerelease.yml` first, so every beta carries an
   IPA to probe with; promote it to `stable-release.yml` only after the device checklist passes.
3. **SideStore source feed** at `https://apps2samsung.com/sidestore/apps.json`, served from `docs/`
   the way the F-Droid repo is, and regenerated by the release workflow with the `CI_PUSH_TOKEN`
   pattern. Source format: SideStore's `App` (name, `bundleIdentifier`
   `nl.madebypatrick.apps2samsung`, `developerName`, `version`, `versionDate`, `downloadURL`, `size`,
   `localizedDescription`, `iconURL`, `tintColor`, screenshots, `minOSVersion`). Stable only in the
   feed, like F-Droid; betas stay a manual IPA import.
4. **Document it** in the README next to the Android section: installation, updates, what a failed
   refresh looks like and how to recover. Do not advertise iPhone support before the complete process
   has been tested end to end by someone other than the person who built it.

## User setup

1. Follow SideStore's prerequisites and installation guide.
2. Connect the iPhone to a computer by USB once and install SideStore with iloader.
3. Trust the developer account, enable Developer Mode where iOS asks for it, and set up LocalDevVPN.
4. Sign in to SideStore with the same Apple ID used during installation.
5. Add the Apps2Samsung source (or import the IPA from a release) and install.
6. Open Apps2Samsung; grant local network access when iOS asks; find the TV; install.

A computer is normally needed once, for the SideStore setup, not for TV installs afterwards. Pairing
problems or an iOS update can require the computer again.

## Limits to state plainly in the README

- Free signing expires after **seven days**. SideStore refreshes in the background, but the user should
  check that refreshes succeed before expiry. An expired app will not open until it is re-signed, and
  if SideStore itself expires, recovery can require the computer.
- Free Apple IDs allow **three active sideloaded apps including SideStore**, so two slots remain.
- Apple limits App ID registrations to ten per seven days; app extensions use extra IDs.
- LocalDevVPN is a local on-device mechanism for installing and refreshing, not a commercial VPN.
- Installing a new version and refreshing the signature are separate operations.
- SideStore changes who signs the app, nothing else: every iOS API, entitlement and compatibility
  restriction still applies. In particular iOS suspends the app in the background, so an install has
  to finish in the foreground (keep-screen-on is in the #753 checklist).

## How this fits v3 and the stores

- **SideStore is the free channel; the App Store is the v3 channel.** Both ship the same build; the
  store build is signed with the paid account in CI, the SideStore IPA is left unsigned. The two
  channels share the release workflow, the version numbering and the feed-generation pattern.
- Running SideStore first costs nothing and answers the device questions before any money goes to
  Apple. If App Store review later refuses a developer-mode TV tool, SideStore stays as the only
  iPhone channel, and it already exists.

## Order of work

1. `ios-ipa` job on `beta-prerelease.yml` (unsigned device publish). First real AOT build.
2. One manual SideStore install on a real iPhone; run the #753 step 5 checklist against a retail TV.
3. Fixes from the probe.
4. Source feed + README section + promote the job to the stable release.
